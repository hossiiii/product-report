規制要点

  • 個人情報保護法(APPI): 顧客データ・PIIがエージェントのコンテキストに入る可能性があり、第三者提供同意、越境移転制限への対応が必要。Runtimeのサンドボックス＋PII遮蔽機能で要件は満たせるが、LLMの学習利用オプトアウト契約をAnthropic/OpenAI側で確実に行う必要がある。
  • 金融庁 FISC安全対策基準 / 外部委託管理: 金融機関導入時はFISC準拠・外部委託管理基準の充足が必須。VPC自己ホストとシングルテナント分離が必要で、Runtimeは技術的にはサポート可能だが、監査証跡の保管期間・国内データセンター対応の明示が求められる。
  • 経済安全保障推進法 / クラウドサービス安全性評価制度(ISMAP): 官公庁・準公的セクター案件ではISMAP登録または同等水準の説明が事実上必須。米国スタートアップの単独参入では取得まで時間がかかり、国内パートナー経由が現実解。

判断ガイド

何をするか
Runtimeは、Claude Code・Cursor・Codex・Gemini CLI等の既存コーディングエージェントを企業の文脈・統合・ガードレール下で誰でも安全に呼び出せる『実行基盤(ランタイム)』。各エージェントは隔離サンドボックス上で動作し、監査ログ・予算上限・PII遮蔽・行レベルスコープ等のポリシーが効く。Slack・Linear・GitHub・ブラウザ・CLI・APIから@メンションで起動し、調査・PR作成・データ問い合わせ・ダッシュボード作成・運用自動化までこなす。BYO API キー、OAuth、VPC自己ホストにも対応し、PagerDuty連動のオンコール調査エージェント、Stripe/NetSuite連携の経理エージェント、Zendeskサポート トリアージなど業務別エージェントをチームが内製可能。エンジニア以外もPRを安全に出せる点が他と異なる。
誰に刺さるか
10〜500人規模の開発組織を持つテック企業、特に非エンジニアにも開発/データ操作を委ねたいPM・GTM・サポート・経理チーム。社内に複数モデル/CLIが乱立し、属人化と監査不能に困っているCTO/プラットフォームエンジニアリングチーム向け。
再現可能性
hard — サンドボックスインフラ、マルチエージェント抽象化、監査ログ、Slack/Linear/GitHub統合、VPC配布、課金まで個人開発では数年単位の投資が必要。
