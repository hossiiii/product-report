商習慣 3/10

日本はメンバーシップ型雇用が主流でジェネラリスト評価が中心、スペシャリスト即戦力評価のジョブ型はまだ移行途中。GitHubのProof of Work重視は大手企業の採用慣行にフィットしない。

国内既存プレイヤー

  • Findy — GitHub連携でスキル偏差値を算出するエンジニア特化スカウト。月額36万円〜＋成果報酬30-35%。日本市場で最有力競合。
  • LAPRAS — GitHub・Qiita・Connpass等のオープンデータを自動収集し転職潜在層をAIでスコア。月額・成果報酬の複数プランを提供。
  • Forkwell — エンジニア勉強会×スカウト。約4.7万人の即戦力エンジニアDBを持ち、スキル別検索が強み。
  • Wantedly — ミッション共感型のダイレクト採用。エンジニア採用での利用も多くスタートアップに浸透。
  • Track Test — コーディングテストによる実務スキル評価。GitHub解析ではないが代替的な実力評価ソリューション。

規制要点

  • GitHub Acceptable Use Policy: Service情報をrecruiter・headhunter・job board向けに販売または利用する目的でのスクレイピング／API取得は明確に禁止。アカウントBANのリスク。
  • 個人情報保護法（日本）: GitHub/LinkedInプロフィールの大量取得・第三者提供には利用目的の通知・公表が必要。本人同意なしの提供は原則違法で、PPCの監督対象。
  • GitHub一般プライバシーステートメント: ユーザー個人情報を本人の利用目的承認なしに収集・利用することを禁止。プライベートリポ閲覧には明示同意必須。

機会: 日本特化版を作るなら、Findy/LAPRAS未開拓のニッチ（例：ゲーム/組み込み/特定言語コミュニティ）×日本語ドキュメント解析×企業のジョブディスクリプション自動生成にピボットする道はあるが、本家のままでは厳しい。

市場機会総評: 需要自体は2030年問題で旺盛だが、Findy・LAPRAS・Forkwellという3強がGitHub連携型スカウトのポジションを既に押さえており、英語ベースのまま参入してもブランド・DBの両面で勝てない。さらに、現状のスクレイピングモデルはGitHub規約と日本の個人情報保護法の双方でリスクが高く、エンタープライズに売り込む際の障害となる。日本の採用文化（メンバーシップ型・新卒一括）ともフィットが悪く、ジョブ型移行の波に乗れるテック寄り企業のみが限定的なターゲット。

判断ガイド

何をするか
GitHubの公開アクティビティとプライベートリポジトリ（候補者同意ベース）をAIで解析し、コード品質・プロジェクト深度・コミット信頼性を基に開発者を自動スコアリングするスカウト採用プラットフォーム。10k+の事前評価済みプール検索とGitHub+LinkedInスクレイパーを内包し、求人説明文から自然言語で最適候補をランキング表示する。料金はセルフサービス$250/seat/月またはhire成功時のみ支払うDFYモデル。
誰に刺さるか
技術スタートアップの創業者、社内リクルーター、開発エージェンシーで、迅速にハイレベル開発者を発掘したい組織。特に英語圏のリモート採用ニーズが強い企業。
再現可能性
medium — GitHub APIとLLMで基本機能は再現可能だが、プライベートリポ同意取得・10k+プール構築・スコアリング精度の検証には相応の時間とデータが必要。

  • GitHub Acceptable Use Policyでrecruiter目的のスクレイピングは明確に禁止
