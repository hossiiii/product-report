規制要点

  • 改正個人情報保護法 (2026 年閣議決定): 違法な個人情報取扱いに対する課徴金制度導入。ソースコードに含まれる個人データの外部 AI 送信に慎重対応が必要。自社インフラ実行モデルは適合しやすい。
  • AI 事業者ガイドライン v1.2 (総務省/経産省 2026/3/31): AI 利用時の機密情報入力、出力検証、ログ保管に関する遵守事項。診断結果の取扱いに準拠が必要。
  • 営業秘密保護 (不正競争防止法): ソースコードを外部 LLM に送信する場合、営業秘密の保護要件(秘密管理性)が崩れるリスク。自社鍵・自社インフラ実行は適合しやすい。

判断ガイド

何をするか
Vercel が OSS 化した AI 脆弱性スキャナで、Claude Opus 4.7 と GPT-5.5 のコーディングエージェントを使い、自社インフラ上でソースコードを調査する。regex による静的事前スキャンで対象ファイルを絞り込んだ後、エージェントが各ファイルを精査し、再検証で偽陽性を削減、git メタデータで担当者を特定、最後にチケット化用フォーマットで出力する。CLI 中心、Vercel Sandbox への fanout で 1,000+ 並列実行も可能。
誰に刺さるか
中〜大規模コードベースを抱える Web/SaaS 開発組織、AppSec 担当者、AI コーディングエージェント (Claude Code/Codex) のサブスクリプションを既に契約している開発チーム。
再現可能性
hard — コアの差別化は Vercel の社内検証実績と Sandbox 連携・プロンプト/エージェント設計のチューニング。表層クローンは可能だが、検出精度と運用コスト最適化に多大なノウハウが必要。

注目シグナル

  • Product Hunt で 252 upvotes、Vercel 公式ブログでの大々的な発表
  • AI コーディングエージェントの企業導入が急増し、生成コードのセキュリティ課題が顕在化
  • GitHub Advanced Security/Snyk など既存 SAST が AI 文脈に追従しきれていない
  • OSS かつ自社鍵・自社インフラ実行で、機密コードを外部に出したくない需要にマッチ
  • Claude Code/Codex の既存サブスクで動くため追加導入障壁が低い

懸念点

  • スキャン 1 回あたり数千〜数万ドルの LLM API コストが発生し、個人/小規模では負担大
  • 誤検知率 10〜20% で、トリアージ運用が必要
  • Vercel が本体 OSS をリードしておりエコシステムの中心は彼ら
  • 日本市場では SAST/DAST 受託ベンダーが強固な販路を持ち、OSS 単体は売りにくい
  • セキュリティ製品は SLA・サポート・責任分界の要求が高く個人開発で受けにくい
