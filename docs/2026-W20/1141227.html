著作権法30-4で情報解析目的の複製は許容されるが、第三者配布や個人情報、利用規約違反、不正競争防止法(限定提供データ)に該当する用途は禁忌。サービス提供側として用途制限・規約整備が必須。

ローカライズ 5/10

対象APIがGoogle/Amazon/Zillow/Booking等の海外サービス寄り。iタウンページ、食べログ、SUUMO、HOME'Sなど国内主要サイト向け専用パーサがなく、日本市場でのUVPが弱い。

商習慣 5/10

日本企業はSaaS導入時に請求書払・日本語サポート・SLA・契約書を要求し、海外APIをそのまま使うのに抵抗が大きい。代行型サービス文化が根強く、セルフサーブAPIの浸透は中速。

国内既存プレイヤー

  • Bright Data — 日本語サポートあり、15,000+顧客。プロキシ網最大手で国内大企業の導入実績多数。
  • Octoparse — ノーコードスクレイピングツール。$99-$249/月、日本語UI完備。
  • PigData — 国内のスクレイピング代行サービス。月額4-10万円が相場。
  • ShtockData Pro — 日本人スタッフサポート、初期費用0円。
  • Apify — Actor市場でカスタムスクレイパー流通。日本でも開発者層に浸透。
  • Firecrawl — Claude Code MCP連携で日本の開発者ブログでも頻繁に紹介される競合。
  • ScrapingBee — $49〜/月、シンプル路線。HasDataと最も近い価格帯。

規制要点

  • 著作権法 第30条の4(情報解析目的の複製): 情報解析目的なら複製可だが、第三者への配布や原コンテンツの再利用は不可。サービス側で用途を限定する規約整備が必要。
  • 不正競争防止法(限定提供データの不正取得・使用等): 他社の有料DBやID/PW保護されたデータを取得・第三者提供すると違法。会員制サイトのスクレイピング機能提供にリスク。
  • 個人情報保護法: 氏名・連絡先等を含む営業リストを大量収集・第三者提供する場合は本人同意や利用目的明示が必要で、用途次第で違反となる。
  • 電気通信事業法・偽計業務妨害(刑法233条): 対象サイトに過剰負荷を与えた場合に業務妨害として刑事責任を問われた判例(岡崎図書館事件)あり。レート制御が必須。

機会: 国内向けに『食べログ/SUUMO/iタウンページ/求人ボックス』等の主要日本サイト専用パーサを揃え、請求書払・日本語SLA・法令ガイドライン込みで提供すれば、海外APIでカバーしきれない営業リスト/不動産/求人エンリッチ需要を取りに行ける。AIエージェント×日本サイト特化スクレイパーはまだ空白。

市場機会総評: 需要は確実にあり、AIエージェント×Web取得というタイミングも追い風。ただし海外プレイヤーの先行と国内代行業者の根強さ、日本サイト向けパーサ整備のコスト、法令運用の重さが組み合わさり、HasDataがそのまま日本市場で勝てる構図ではない。日本特化リスケラピングSaaSとしてのリパッケージなら勝機あり。

判断ガイド

何をするか
Web上の任意URLから構造化データ(JSON/Markdown)を取得するマネージドAPI。プロキシ、ヘッドレスブラウザ、リトライ、アンチボット回避を内製し、Google SERP/Maps/Amazon/Zillow等の主要サイト向けに40+の専用エンドポイントを持つ。さらにAI Extractionで任意ページもプロンプト指定で構造化可能。MCPサーバ・CLI・Claude Code Skillが同梱され、AIエージェント側から自然言語で呼べる点が新規性。
誰に刺さるか
営業リスト作成、価格モニタリング、AIエージェント用RAGデータ収集、CRMエンリッチ、検索結果分析を行う開発者・データチーム・SaaSプロダクト開発者。
再現可能性
hard — プロキシプール、ヘッドレスブラウザ群、アンチボット運用、40+の対象別パーサ維持と、価格競争力ある成功課金モデルを個人で再現するのは困難。
