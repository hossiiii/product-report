国内既存プレイヤー

  • Jina Reader (r.jina.ai) — URL 先頭に r.jina.ai を付けるだけで任意 Web を LLM 向け Markdown 化。日本語対応・国内記事多数で認知度高。X 専用ではないが上位互換的に競合し、無料枠もある最大の脅威。
  • xmdbot — X の記事・スレッド・投稿をクリーン Markdown へ変換する無料ツール。@xmdbot へのリプライで永続リンク生成も可能。tweet.md とほぼ同一ポジションの直接競合。
  • X Copy Tweet as Markdown / Twitter to Markdown 等 Chrome 拡張 — ブラウザ上でワンクリック Markdown 化する無料拡張群。日本語対応のものもあり、ブラウザ内処理で API 原価不要。手動用途では十分な代替となる。
  • tweet-to-markdown (OSS CLI) — ツイートを Markdown 化する CLI の OSS。開発者・自動化用途で無償の代替手段。日本の開発者の OSS 志向と相性がよく、課金型サービスの圧迫要因。

規制要点

  • X 利用規約 / 著作権法: X 規約は書面許可なきスクレイピング・技術制限回避を禁止し、取得コンテンツの公開・販売・再配布は著作権上も無制限には許されない。投稿テキストの再提供を中核とする本サービスは規約・著作権の双方でグレーゾーンを抱え、X 側の方針変更でサービス停止リスクが常在する。
  • 個人情報保護法: 公開投稿でも顔画像・健康・思想信条等の要配慮個人情報を機械的に大量取得・再提供する場面では個情法上のリスクが高まる。取得対象の選別と必要性の検討が必要で、無差別な投稿変換は留意が要る。
  • 電気通信事業法（外部送信規律）: 国内向けに Web サービスを提供する場合、外部送信規律（Cookie 等の利用者情報の外部送信に関する通知・公表義務）の対象になり得る。本サービスは決済後に Cookie で API キーを配るため、Cookie 利用の通知設計に留意が必要。重大な障壁ではない。

判断ガイド

何をするか
X（旧Twitter）の投稿 URL の x.com を tweet.md に置き換えるだけで、投稿・スレッド・引用・記事を LLM が読みやすいクリーンな Markdown として返すサービス。HTML スクレイピングや画面コピーで生じる埋め込み・スクショ・余計な装飾を排し、出典（ハンドル・日時）を保持する。API と AI エージェント用スキルも備え、ChatGPT・Claude・Claude Code・Cursor・Codex・Obsidian・NotebookLM などの LLM/ノートワークフローに組み込める。典型ユースケースは、リサーチ用に X スレッドを RAG やプロンプトに流し込む、Obsidian へクリップして恒久保存する、エージェントが会話中に投稿内容を取得する、など。最近は X プロフィール取得にも対応。
誰に刺さるか
AI ワークフロー・リサーチ・ノートテイキングで X の公開投稿を素材として扱う開発者・パワーユーザー。具体的には Obsidian/Notion ユーザー、RAG やエージェントを組む個人開発者、LLM ヘビーユーザー。日本でも該当層は存在するが英語圏中心でニッチ。
再現可能性
medium — URL リライト + Markdown 整形自体は容易だが、X の投稿データ取得が肝。公式 X API は新規開発者が従量課金（1 読込 $0.005）のみで原価が嵩み、非公式スクレイピングは ToS 違反リスク。データ供給の安定確保が難所。
