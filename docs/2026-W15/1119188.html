規制要点

  • 景品表示法・薬機法（広告生成skill利用時）: /ads /blog skillで業界規制対象の商材（医薬品・化粧品・金融等）の広告コピーを生成する場合、ユーザー責務として優良誤認/有利誤認・薬機法表現の点検が必要。フレームワーク提供者には直接規制は及ばないが、JP版を出す場合は注意喚起をdocsに明記すべき。
  • 特定電子メール法: /email skillでイベントフォローシーケンスを送る際、JPではオプトイン取得・送信者表示・配信停止導線が必要。skill側でこの遵守項目を組み込まないとJPユーザーが法令違反メールを送るリスクあり。
  • 著作権法・OSSライセンス: MITのため利用・改変・商用利用は自由。ただし生成物に他者著作物が混入する画像生成skill（/image）でフェアユース概念が無いJPでは引用要件遵守が必要。

機会: JP角度は『Claude Code marketing skill群の日本語ローカライズフォーク』。具体的には(1)channel directoryをQiita/Zenn/note/X/はてブ/connpassに差し替え、(2)/social-posts skillをLinkedIn→X+Qiita+note tri-publishに改修、(3)AI臭検出skill（16-minds等）の組込、(4)JP B2B向けに紹介依頼テンプレ・代理店向けピッチskillを追加、(5)景表法/特電法/薬機法チェックskillの同梱。本家MITなのでフォーク即可、ブランドは『日本のインディーメイカー向けGTM箱』として差別化可能。

市場機会総評: 需要はある（demand 7）が、本家フレームワークの英語圏前提が日本では深い改修を要求する（localization 4）。同種のskill断片（AI臭除去・3媒体クロス投稿等）は既に日本語OSSで公開されており、本家を丸ごと持ち込むより、それらと結合した『JP統合版』を出す形が現実的。規制リスクは低く（regulation 9）、フォーク自体は容易だが、JP B2Bの代理店文化やPLG非適合な業界が多い点で商習慣スコアは中庸。総じてjapan_fit 6＝『watch』。OSSとしてフォークし、JPコミュニティへの貢献として運営する分には筋が良いが、独立プロダクトとして勝負する案件ではない。

判断ガイド

何をするか
Claude Code/Codex上で動作するOSS（MIT）のマーケティングskill集。`git clone`してdocs/inputs/配下の6つのMarkdown（product_brief, target_personas, messaging_positioning, competitor_intel, testimonials, brand_guidelines）を埋めると、`/social-posts`（LinkedIn/X投稿）、`/email`（イベントフォロー）、`/blog`（SEO/AEO最適化）、`/ads`（Google/Meta/LinkedIn広告）、`/sales-deck`（April Dunford流B2Bデック）、`/messaging-positioning`（ソクラテス式ワークショップ）、`/image`（MCP経由の画像生成）、`/editorial-calendar`、`/launch-roundup`、`/skill-builder`、`/autoresearch`の11 skillと、競合調査・QA・広告最適化の3 agentが製品文脈付きで成果物を生成する。SaaSではなくリポジトリそのもの。
誰に刺さるか
developer tools / B2B SaaSを個人〜小チームで開発し、自前でマーケを回さねばならないインディーメイカー。専任マーケを雇えず、April Dunford流ポジショニングやMKT1コンテンツプランを自前で書きたい層。日本では「1人マーケ部門を作りたい」個人開発者・副業エンジニアが該当。
再現可能性
easy — MITライセンスのGitHubリポジトリで全skill定義が公開。日本語ローカライズ・チャネル直し（Qiita/Zenn/note追加、AI臭除去）を加えれば差別化フォークは容易。

懸念点

  • MIT・無料・寄付モデルでマネタイズパスが不明（GitHub Sponsorsは日本だと月数万円が現実的）
  • /ads /sales-deck はApril Dunford等の英語圏フレームワーク前提で、JP B2B商習慣（コンペ・代理店経由）と噛み合わない
  • LinkedIn前提のskillが多く、日本ではX/Qiita/Zenn/noteへの差し替えが必須
  • 日本語生成時のAI臭問題（接続詞過多・締めの定型文・---区切り）への独自対応が無い
  • 本家がdaily updateで急進化しており、フォーク版が追従コスト負担になる
