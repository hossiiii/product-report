国内既存プレイヤー

  • Notta — 国内で普及する AI 文字起こし・議事録 SaaS（個人 ¥1,317/月〜）。会話の記録・要約という点で重なるが、常駐キャプチャや Claude への MCP 文脈供給は非対応で用途が異なる。
  • Obsidian / Tolaria 系 PKM — ローカル Markdown のセカンドブレイン。AI 連携 vault（Tolaria 等）が文脈供給層として登場。手動蓄積中心で受動キャプチャではない点が Minimi と異なる。
  • Claude 純正メモリ（Anthropic） — 競合は国産ではなくプラットフォーム本体。Chat/Project/API の3層メモリを 2026 年 3 月に全プラン開放済み。会話横断の記憶を無料で内包し Minimi の価値と重複。

規制要点

  • 個人情報保護法: 会議音声・チャット・画面に映る第三者の情報を常時取得するため、識別可能な個人情報の取得・利用目的の明示・安全管理義務が発生しうる。オンデバイス保存でも漏えい時の責任は残り、業務文脈では取得同意の論点が大きい。
  • 電気通信事業法（外部送信規律）: 完全オンデバイスなら対象外となりうるが、サインイン・ライセンス認証・テレメトリ等で端末情報を外部送信する実装があれば、送信情報の内容・送信先・目的の通知/公表または同意取得が必要になりうる。
  • プライバシー権（無断録音の判例リスク）: 日本では秘密録音自体は直ちに違法ではないが、目的・態様・第三者への開示次第でプライバシー侵害が認定された判例があり、損害賠償リスク。常時音声キャプチャは相手の同意取得運用を促すべき。

機会: 国内独自の角度は、(1) 日本語の OCR・会議文字起こし精度に最適化し「日本語で正確に想起できる常駐メモリ」を打ち出す、(2) Claude 純正メモリが弱い「会話の外（自分の PC 活動・閲覧・通話）」の文脈に特化して住み分ける、(3) プライバシー懸念が強い日本市場でオンデバイス完結を前面に出し、情シス向けに「データが端末外に出ない監査可能な設計」を訴求する点。個人開発者・PM・コンサルなど Claude ヘビーユーザーの個人利用に絞れば、純正メモリと補完関係を築ける余地がある。

市場機会総評: 市場機会としては中庸。Claude/MCP の JP 利用は活発で、パーソナル AI メモリ概念の認知もあるため需要素地はある。国産の直接競合も見当たらず、競合軸は良好。一方で最大の脅威は国産他社でなく Claude 純正メモリ（2026 年 3 月に全プラン開放）で、コア価値が重複する点が機会を縮める。規制面は完全オンデバイスなら軽いが、他者情報の常時キャプチャに伴う個情法・プライバシー論点が業務利用での導入摩擦になる。ローカライズは MCP/オンデバイス中心で容易だが、日本語 OCR・文字起こし精度が実用性を左右する。総じて「即時参入の build」ではなく、純正メモリとの住み分けとプライバシー設計を検証しながら様子を見る watch が妥当。

判断ガイド

何をするか
Mac のメニューバーに常駐し、ユーザーが許可したアプリ上の活動（閲覧したタブ、編集ドキュメント、通話音声、Slack スレッド等）を受動的にキャプチャ。オンデバイスのベクトル DB に蓄積し、MCP のカスタムコネクタとして Claude に1リンクで接続する。Claude 側から「今朝のフォローアップは？」「昨日の会議で何を決めた？」「金曜までに何を送ると約束した？」といった質問に、過去数週間の文脈をもとに回答できる。データは端末外に出ない設計で、キャプチャ対象アプリを個別に選択・一時停止可能。BEAM ベンチで 54%（従来 SOTA 36%）と主張。典型用途は ToDo の抽出、会話相手・経緯の想起、フォローアップ管理、自分の活動ログの振り返り。
誰に刺さるか
Claude を日常の業務ハブとして Mac 上で多用するナレッジワーカー、コンサル、開発者、PM。セッションごとに文脈を再説明する手間を嫌い、過去の活動を AI に横断検索させたい個人ユーザーが主対象。MCP を自分で設定できるリテラシー層。
再現可能性
medium — MCP サーバ実装と Mac 常駐キャプチャ（画面 OCR・音声・各アプリ連携）は実装可能だが、低ノイズで高精度な想起、オンデバイスのベクトル検索最適化、安定した常駐動作の作り込みが差別化点で工数大。
