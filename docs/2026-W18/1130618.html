  • Rancher (SUSE) — 国内エンタープライズで強い。SUSE Japan経由の保守契約あり。マルチクラスタ管理プラットフォームの定番。

  • 著作権法 / OSSライセンス: Apache 2.0なので商用利用・改変・再配布可。フォーク/派生での商用化は法的に可能だが、本家との差別化が実質課題。

判断ガイド

何をするか
Radarは、kubectl/Lens/Headlamp/k9sなど分散していたKubernetes運用を一つのUIに統合するOSSダッシュボード。所有関係を表現するトポロジ表示、全リソースのライブイベントストリーム(watch API)、Helmのdiff/rollback、Argo CD/Fluxのネイティブ同期、Hubble/Cilium/Caretta/Istioによるトラフィック可視化、OpenCost連携のコスト分析、31項目のクラスタ監査、コンテナイメージのファイルシステムビューア、CursorやClaudeを接続できるMCPサーバーを内蔵。単一Goバイナリで配布、Apache 2.0、アカウント登録不要。Radar Cloud(SaaS)はフリート集約・永続保持・SSO等の追加用途のみ。典型ユースは複数クラスタの障害調査、Helm差分確認、コスト按分、セキュリティ監査、AIエージェントへのクラスタ情報提供。
誰に刺さるか
複数Kubernetesクラスタを運用するSRE/プラットフォームエンジニア/インフラエンジニア。Lensの有償化に不満を持つ層、FreeLensのElectron重さを避けたい層、k9sのCLIでは情報量が足りない層、CursorやClaude等のAIエージェントにクラスタ操作権限を渡したい開発者。エンタープライズPlatformチームも対象。
再現可能性
hard — Kubernetes APIへの深い対応、Helm/Argo/Flux/Hubble/OpenCost等20+ツールとの統合、トポロジ可視化、MCP実装が必要。OSSのため模倣でなく差別化が困難。

注目シグナル

  • PH 403 upvotes / GitHub 2.1k stars - 初動の関心は高い
  • Lensの有償化で乗り換え需要が国際的に発生中
  • MCPサーバー内蔵でAIエージェント時代の文脈を取り込む
  • Apache 2.0 + アカウント不要で導入摩擦が極めて低い
  • 本家(skyhook-io)はYC W23、開発リソースは個人開発者の比でない

懸念点

  • 本家OSSが完全無料・機能制限なしのため、第三者(個人)が同領域で課金する余地が乏しい
  • Radar Cloud(本家SaaS)が既存マネタイズ枠を全方位で抑えに来る
  • 国内Kubernetes実運用層が薄く、日本語化単体の付加価値は限定的
  • 競合(Lens/Headlamp/FreeLens/k9s/Rancher)が多数存在し差別化困難
  • 深いk8s知識が必要で個人開発者の参入ハードルが高い
