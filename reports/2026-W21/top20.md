- [メタリアル Metareal オーディット](https://www.metareal.jp/) — 内部リスク評価報告書作成のAIエージェント。監査領域のAIエージェントだが、開発者向けエージェント活動のVCSとは用途が異なる。間接的な参照として記載。


**規制要点**:
- **個人情報保護法**: ローカルCLIで完結する限り影響は軽微。ただしチーム共有・クラウド同期機能を提供する場合、プロンプト中に含まれる個人情報や顧客データが外部送信される可能性があり、利用規約・プライバシーポリシーで取扱いを明示する必要がある。
- **著作権法**: エージェントが生成したコードを保存・再生する性質上、第三者OSSの取り込み履歴が記録される。直接的な規制違反リスクは低いが、Apache-2.0などライセンス遵守の運用設計が望ましい。


**機会**: 日本独自開発の角度としては、(1) 受託開発・SIerの納品物として『AIが書いたコードの来歴証明』を提供するエンタープライズ版、(2) 国内クラウド(さくら・IIJ等)で完結するチーム共有SaaS、(3) Backlog/Redmineといった国内チケット管理ツールと連携し『どのチケットのどの指示でこのコードが生まれたか』を追跡するインテグレーション、(4) 個情法・金商法等の監査要件に対応した監査ログエクスポート機能、が考えられる。OSSコアは本家にコミットしつつ、日本企業向けのコンプライアンス層・チーム機能をSaaSで提供する戦略が現実的。

**総評**: AIコーディングエージェントの活動履歴をGit的に管理するという課題自体は、日本でも『エージェントが14ファイル暴走編集』『本番DB消去事故』のような事例で顕在化しつつあり、需要は中〜中上位。国内に直接競合がほぼ不在で参入余地は大きいが、Anthropic/Cursor本体のcheckpoint機能拡張が継続的脅威で、コア機能だけでの差別化は持続困難。一方、日本企業特有の監査ログ要求・受託開発の説明責任・既存チケット管理ツール統合という方向で価値を積み上げれば、エンタープライズ向けに独自の角度を取れる。OSS Free Foreverゆえ収益化パスは別途設計が必要。総合的にwatch判定とし、本家機能の進化と国内エンタープライズの監査要件動向を見極めつつ、Backlog連携やコンプライアンス対応SaaSとしての差別化検討を継続するのが妥当。



### 判断ガイド（製品概要）

- **何をするか**: rgt log / rgt blame / rgt sessions などのCLIコマンドを通じて、Claude CodeやCursorといったAIコーディングエージェントの全アクション(ファイル編集・プロンプト・セッション)をローカルでキャプチャし、Gitとは別レイヤーでバージョン管理する。各ファイルの行単位で「どのプロンプトが書かせたコードか」をblameでき、セッションが/compactで圧縮・断片化されても履歴を保持。複数エージェントを並列実行してもセッションごとにブランチが切られ衝突しない。エージェントが14ファイルを暴走編集した時の原因特定、安全なundo、過去セッションの再生(replay)、チームメイトとのコンテキスト共有が主なユースケース。Apache-2.0のOSSでPublic Alpha段階。
- **誰に刺さるか**: Claude Code / Cursor / Codex などのAIコーディングエージェントを日常的に使う個人開発者・OSS開発者、エージェントの暴走で本番事故を経験したスタートアップ、AIエージェント導入企業のSRE・プラットフォームエンジニア。エンタープライズ側では監査ログ要件の強いSIer・受託開発企業。
- **再現可能性**: `medium` — ファイル監視・プロンプトキャプチャ・Git類似のローカルストレージ実装で技術的難易度は中程度。1〜3ヶ月で動くPoCは可能だが、複数エージェントCLIへの対応と信頼性確保には継続的な対応が必要。
- **注目シグナル**:
  - Public Alpha段階でPH 170 upvotes・34コメントと反応良好
  - GitHub Issue #21645等でClaude Code本体にもrollback要望が出ている顕在化した課題
  - Cursorエージェントが本番DB+バックアップを9秒で消去した事件など、エージェント暴走による事故が報道されている
  - Apache-2.0でFree Foreverを宣言、開発者コミュニティの取り込み戦略が明確
  - セッション圧縮(/compact)後の履歴保持という具体的pain pointを解決

- **懸念点**:
  - Anthropic/Cursor等の本体側がチェックポイント機能を内蔵し始めており差別化が浸食される可能性
  - Free Forever宣言で収益化パスが不透明(チーム共有/SaaS版が必要)
  - 外部API・DB等の副作用までは追跡できない(コメントでも指摘)
  - 対応エージェントの種類とフックの実装コスト
  - ローカルストレージのみだとチーム共有・監査用途の訴求が弱い
